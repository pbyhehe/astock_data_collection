# 停牌日期归属 `astock.suspension`

纯函数 `classify_suspension(details, query_date, completed_through) -> str`，不联网、不写数据库。details是保留来源字段的事件列表，日期为ISO字符串或NULL。供扩展校验、存储复核及v3→v4迁移共用。

实测 `stock_tfp_em(date="20260909")` 返回的部分记录从2026-09-15才开始停牌。因此来源列表成员不能直接解释为查询日已经停牌。

| status | 判定 | 不代表什么 |
|---|---|---|
| suspended | 查询日已结束，且来源开始日期等于查询日，或开始/截止两日期明确覆盖查询日；有一条事件满足即可 | 不保证全天停牌，不保证不可交易，AKShare已丢失时分秒 |
| announced | 没有满足上述条件的事件，但存在开始晚于查询日或观察时已结束日期的计划 | 不代表查询日已经停牌，也不代表计划后来必定实施 |
| unknown | 无记录、开始日缺失、日期矛盾、过期事件，或开始早于查询日但缺少确认截止日 | 不等于未停牌，不从缺K线/零成交/预计复牌时间推断 |

来源记录和所有事件仍原样保留在suspension_details_json/raw_json中；只保守解释应用派生status，不改日期、不补截止日。**预计复牌时间绝不当作确认截止日**。默认采集结束于上海昨天，未来显式查询也不会直接标为已停牌。

v4迁移以原请求完成时间在上海对应的昨天作为当时可证明的截止日，避免今天已经过去的计划被倒推成早先已确认事实。迁移修正旧派生标记时，先保存完整旧行至record_revisions，沿用同一证据collection_id，不伪造新来源请求，不修改原始JSON和进度。详见 [迁移模块](migrations.md)。

测试见tests/test_suspension.py：未来安排、未知结束、显式闭区间、缺失/矛盾日期、多事件、采集时尚未结束的日期、存储复核、原证据审计和迁移失败整批回滚。
